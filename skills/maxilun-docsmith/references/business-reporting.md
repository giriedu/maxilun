# Evidence-Based Business Reports

Use for performance reviews, KPI reports, operational diagnostics, and executive summaries. This Maxilun method structures the work around evidence, interpretation, and an actionable decision.

## 1. Establish the report charter

Record these inputs before choosing sections or charts:

- **Audience and decision**: who will read the report, what decision should it enable, and what do they already know?
- **Scope and period**: business unit, product, geography, date range, and comparison baseline.
- **Sources**: supplied files, tables, CRM exports, stakeholder notes, and methodology. Cite a source beside each material finding.
- **Data gaps**: use `[NEEDS USER INPUT: ...]` for missing baselines, units, periods, targets, or definitions. Do not backfill with plausible values.

If a missing input changes the conclusion, ask for it before presenting a verdict. Otherwise proceed with a clearly labeled limitation.

## 2. Build one decision narrative

Use only sections needed by the charter. A common structure is:

1. **Executive summary** — verdict, key findings, top risk/opportunity, and recommended decision. It should stand alone and agree with the body.
2. **KPI snapshot** — a focused set of primary metrics with value, unit, period, comparison, source, and one-line interpretation.
3. **Trends and findings** — organize by theme and severity, not chronology. Each finding links observation → evidence → business impact; mark causal explanations as inference unless the data establishes them.
4. **Recommendations** — each initiative references a finding and names actions, priority, horizon, success measure, and owner type when known. Label expected impact as a hypothesis unless it is supported by a model or historical evidence.
5. **Appendix** — definitions, methodology, detailed tables, and lower-priority metrics when the audience needs an audit trail.

The report is a path from evidence to action. Remove analysis that is interesting but does not inform the stated decision.

## 3. Keep analysis auditable

- Separate **Fact**, **Interpretation**, and **Recommendation** in wording or layout.
- Define how severity is assigned (for example, target miss, negative trend, or approved risk threshold); do not invent thresholds.
- Flag anomalies, missing periods, inconsistent metric definitions, sample-size limits, and source-quality issues.
- Do not fabricate benchmarks, forecasts, owners, ROI, causes, or impact estimates. Use `[INFERRED]`, `[ASSUMED]`, or `[NEEDS USER INPUT: ...]` where appropriate.
- Ensure every summary statement is traceable to a finding and every recommendation points back to an identified finding.

## 4. Match visuals to the question

- Use a line chart for change over time, ranked bars for comparison, contribution/stacked bars for composition, and a table when precise values matter more than shape.
- Put units, periods, baselines, and sources in labels or notes. Never encode meaning with color alone.
- Give the verdict and highest-severity items strongest hierarchy; reduce visual weight for secondary metrics. Avoid a chart dump or decorative dashboard layout.
- Design for the reader's format: skim-friendly summary for leadership, methodological detail for analysts, and appendices for auditability.

## 5. Output format

Use the user's requested deliverable format and the available Maxilun document/presentation workflow. Keep the semantic report plan separate from layout decisions, then create and review the requested document or presentation. Do not change the output format without the user's direction.

## Review checklist

- Charter identifies audience, decision, scope, period, baseline, and data sources.
- Executive summary is readable alone and matches the detailed findings.
- Each material KPI includes unit, comparison, period, and source.
- Findings are prioritized with evidence and impact; inferences are labeled.
- Recommendations map to findings and include a measurable success criterion.
- Data gaps, methodology, and limitations are visible; unsupported numbers are absent.
- Charts answer a question and remain readable in the requested output format.
